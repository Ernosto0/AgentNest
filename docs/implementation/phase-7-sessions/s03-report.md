## Contract adaptations and limits

1. `OAuthState.invalidated_at` is an additive offline schema adaptation. A state consumed before a network call must still be invalidatable by a concurrent disconnect; single-use alone cannot prevent stale callback resurrection.
2. Short-exchange flat and wrapped envelopes and `permissions` are synthetic provisional contracts. Requested scopes are never assumed granted. Live research/recordings must verify response shapes, scopes, subscription requirements and story behavior before acceptance.
3. The state-machine helper requires explicit `reauthorized=True` for a newly authorized connect reusing a disconnected row or replacing authorization on a connected row. Ordinary disconnected transitions remain terminal, and repeating disconnect without erasure keeps its existing 409 response.
4. The session brief requested synchronous erasure, while the earlier security document described a within-24-hour job. Existing send reconciliation requires its draft/message evidence. The operator approved synchronous erasure when safe and durable deferred erasure for unresolved sends, with immediate token/payload removal. `RescheduleJob` preserves the wait without exhausting three retries. Unexpected failures use existing dead-job recovery, and dead cleanup continues to block Meta authorization. No unconditional 24-hour deadline is claimed while reconciliation/operator recovery is pending. The response remains the disconnected account; a separate cleanup-status UI is outside this session.
5. Refresh has no visible customer send/publish effect, so a crashed refresh may repeat the same encrypted credential after a two-minute attempt lease. Completion fences prevent replacing newer credentials. The original operation is tied to the job ID across midnight. Tokens never enter the ledger; only a ciphertext fingerprint and job ID are in its reference, and only expiry is in its result.
6. Real-account OAuth, webhook subscription, live refresh, S3 behavior, revocation and publication remain unverified. Session 1's mock/local defaults, Meta/S3 requirement, reserved local-media tunnel setting and unsupported mixed mock/S3 publishing limitation remain unchanged.
