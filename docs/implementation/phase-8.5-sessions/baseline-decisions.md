## Decisions for Sessions 02–05

| Decision | Contract |
|---|---|
| Shell breakpoints | Under 768 px: five bottom tabs (Today, Inbox, Content, Approvals, More); 768–1199: compact sidebar with available expanded labels; ≥1200: 224–248 px expanded sidebar. Phone gutters 16–20 px, tablet 24 px, desktop 32–40 px. Verify Turkish labels at 360/390/768/1024/1440/1920 in migration sessions. |
| Content widths | Fluid work area capped near 1440 px for dashboard/list-detail/editor. Readable forms 560–760 px. Remove shell-wide `max-w-3xl` in 04; feature-specific split layouts remain in their sessions. |
| Existing URLs | Retain every router path, `/more`, invite token paths, report date/key/snapshot and `account`/`tab`/`status` meanings. Selected nested routes mark their parent navigation item. New shell grouping never renames existing routes. |
| New view state | Mutate a copy of `URLSearchParams` so unrelated values survive. User-selected tabs/views use history entries where Back should restore selection; normalization may replace. New inbox filter state belongs to 07 (`attention` using the existing enum); approval `tab` and selected `approval` belong to 12; content `view=library\|agenda` belongs to 10 if implemented. Invalid values safely fall back without effectful actions. No sensitive draft text in URLs. |
| Account selection | Keep account selection local to existing account-scoped pages, preserving `account` in links and query keys. No global shell account selector or implicit new default. The current Agent page picks the requested existing account or first non-disconnected account; WorkFrame currently picks requested/first ID. Their validation/fallback alignment belongs to 13–17; foreign IDs remain server-rejected. Workspace switching drops old tenant detail/account IDs; Session04 may preserve a safe section/filter mapping, documented and tested against current switch behavior. |
| Workspace switching (Session04 refinement) | Preserve safe list/section paths and the explicit per-section filter whitelist in `app/layout/navigation.ts`: content `tab`/`status`/`view`, inbox `attention`, approvals `tab`, notifications `filter`, activity `group`/`date`. Detail routes fall back to their list/overview, supported knowledge category URLs remain usable, and unknown routes fall back to workspace home. Drop account/customer/conversation/task/approval/cursor/snapshot and arbitrary query IDs. This reviewed refinement preserves the previous section-switch behavior while eliminating cross-tenant resource URLs; same-workspace direct links/queries remain intact. |
| Destination launcher | Include in 04: localized navigation destinations only; Ctrl/Cmd+K, Escape, focus entry/return, keyboard selection, role/demo filtering. Label as navigation, not global record search. It must not submit the existing natural-language commands, fetch private record contexts, or imply a search backend. |
| Icons and identity | Extend `components/icons.tsx` (24×24, stroke 2, hidden decorative SVG). Keep AgentNest text identity. No approved standalone product-mark asset exists in the app; no concept nesting mark or fictional assistant name is adopted. |
| Font packaging | Locally bundle normal variable Manrope headings and Inter body, weights 400–700, Latin + Latin-ext (Turkish), with source/version/hash and OFL license. Prefer pinned distributable assets; no runtime CDN. `font-display: swap`, explicit fallbacks and measured CLS in 02. Avoid downloading unrelated scripts or imagery. |
| Tokens | Semantic canvas/surface/navigation/text/action/state/focus tokens and type/spacing/motion roles from the UI spec; inverse navigation focus must contrast on dark surface. One light workspace; dark navigation specimens are not an app dark-mode promise. |
| Overlay migration | Preserve existing BottomSheet consumer API where practical; central focus trap/return, Escape, background inertness, safe areas, scroll containment in 03. Longer feature editors and dirty-state behavior remain explicit later-session responsibilities. |
| Auth | Retain existing email/password and invite semantics, password managers, paste and `RequireAuth` return-to routing. No signup, reset, session manager or security UI without delivered Phase 8 contracts. Wizard still uses three steps and existing market-default override logic. |

## Typed data-source map

All endpoint suffixes below are under `/api/v1/workspaces/{workspace_id}` unless marked global. Types originate in `frontend/src/api/schema.d.ts` and aliases in `api/types.ts`; hooks are authoritative cache/scope owners.

| Proposed concept region/claim | Delivered typed source and scope | Decision |
|---|---|---|
| Business greeting, date, timezone, currency | `useMe` (`MeResponse`, global `/auth/me`), `useWorkspace` (`WorkspaceOut`), report date helpers | Use actual identity/workspace and workspace timezone. No fictional studio/owner. |
| DM/message counts, approvals, failures, held content, response durations | `useDailyReport` (`DailyReportOut.metrics: MetricOut[]`, `/reports/daily`); metric keys and evidence controlled by report backend; `useMetricItems` for saved date/key/snapshot | Reuse current definitions and authorized subset. Missing metric is absent, not zero. Median duration stays a duration. |
| Weekly trend, percentage increase, time saved | No delivered complete comparative series/time-saved definition in current hooks | Omit. A chart/percentage needs a separately reviewed contract; current report day navigation is not a series API. |
| Upcoming content | `useUpcomingPosts` (`ContentItemOut[]`, `/content-items?tab=scheduled&limit=3`) | Show bounded preview, not total scheduled count or full calendar. |
| Recent content failures | `useRecentFailures` (`/content-items?status=failed&limit=3`) | Bounded newest-three preview; report metrics provide totals if authorized. |
| Planning calendar/empty days | `useContentItems` consumes only `.items`; backend list default `limit=50`, maximum bounded; no range-complete client hook | No complete calendar claim. Session10 must prove range membership/pagination or deliver explicitly bounded agenda and name the missing contract. |
| Content images | `useMediaPreview`/media hooks (`MediaAssetOut`, authenticated workspace-scoped `/media/{media_id}/content`), `ContentItemOut.media_asset_id` | Only actual uploaded media. Stable missing/removed placeholders. No concept photos or external image CDN. |
| Assistant active/paused/controller state | `useAgentOverview` (`AgentOverview`, `/accounts/{account_id}/agent`), social-account capabilities/status | Connection alone does not mean assistant active. No generic animated working state. |
| Assistant current work/recent actions | `AgentOverview.session_counts`, `.recent_actions`; `useAgentTasks` (`Page_TaskOut_`, account tasks), `useWorkThreads` (`threads`) | Show exact returned states and bounded history; no invented activities or fabricated timestamps. Task list exposes next cursor but current overview calls only first20. |
| Owner questions/comments/private memory | `agent-work/hooks.ts`: account-scoped questions, comments, customers/memory/sources | Keep `account` in links. Memory never fetched/rendered for public comments. Answer/clarification never implies approval. |
| Approval badge | `useApprovals` (`ApprovalOut[]`, `/approvals`) or authorized report `pending_approvals_now` | Count only authoritative returned/current scope; no list-length total if list completeness unproved. Do not mount a new report solely for shell decoration. Omit shell approval count initially. |
| Notification unread count | `useNotifications` (`NotificationList.unread_count`, `/notifications?limit=30`) | Use server unread count, preserve typed destination mapper and mark-read semantics. Never infer total from first30 items. |
| Inbox unread/attention badge | `useConversations` (`ConversationOut[]` with attention); no separate complete unread-count contract | No invented inbox unread badge. Existing report `attention_now` remains a distinct authorized metric. |
| Knowledge completion | `useReadiness` (`ReadinessOut.requirements`, `/readiness`), facts/templates/candidates hooks | Actual requirement progress; fact usability/verification distinct. No generic business completion percentage from invented checklist. |
| AI mode/simulation | global `useMeta` (`MetaResponse.llm_mode`); account/record `is_simulated` | Compact shell explanations in 04, keep per-result badges and urgent reauth/degraded notices. Workspace demo flag is context, not authority to label all live effects simulated. |
