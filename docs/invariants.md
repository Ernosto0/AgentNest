# Non-Negotiable Engineering Invariants

**Purpose:** Properties that must hold in every phase, every environment and every code path. Each one names its **enforcement mechanism** and the **tests** that prove it.
**Rule for implementers:** If a task cannot be completed without violating an invariant, stop and raise it. Do not weaken an invariant to make a feature work. Any change to this file needs an ADR.

| ID | Invariant | Enforcement mechanism | Proven by |
|---|---|---|---|
| **INV-01** | **One workspace never accesses another workspace's data.** | `workspace_id NOT NULL` on all tenant tables. Composite FKs `(workspace_id, id)`. `require_membership` route dependency. Repositories require `WorkspaceContext`. Webhooks resolve workspace from the receiving account, never from payload claims. RLS in Phase 8. ([ADR-013](architecture/decisions/ADR-013-authentication-and-tenancy.md)) | Isolation test suite (`tests/isolation/`): every endpoint is called with foreign IDs and must return 404. DB tests: cross-workspace FK insert must fail. |
| **INV-02** | **Business-critical facts are never fabricated.** Prices, hours, contact details, addresses, URLs, policies and promotion terms in customer-facing or published text come only from **verified, usable** facts. | Placeholder rendering + claim validator ([ADR-008](architecture/decisions/ADR-008-structured-business-knowledge.md)). Only `usable` facts are offered to LLM tasks. Extraction yields candidates, never facts. | Validator unit tests (TR/EN patterns). Eval hard assertion: **0 ungrounded critical values** in drafts that pass validation. Integration test: an unverified price is never rendered. |
| **INV-03** | **Customer-supplied content is untrusted data, never instructions.** The same applies to extracted website and pasted text, media and webhook payloads. | Untrusted text is only placed inside labelled data blocks of LLM inputs. LLM tasks have no tools. Customer input can never reach the command interpreter. Injection heuristics escalate. ([security-and-privacy.md §4](architecture/security-and-privacy.md)) | Injection eval set. Unit test: no code path from `inbound_events` or `messages` to `CommandService`. |
| **INV-04** | **An LLM cannot bypass permissions or approval requirements.** | LLM output is parsed into closed schemas and is only ever a *proposal*. The policy engine is deterministic, and LLM flags can only make it stricter. Execution re-checks approval binding and permissions of the **human** actor. There is no "approve" command type. ([ADR-014](architecture/decisions/ADR-014-approval-and-policy-model.md)) | Policy engine table tests. Test: fake LLM returning `needs_human=false` for a complaint still escalates. Test: executor refuses without a valid approval. |
| **INV-05** | **External operations have a verifiable outcome.** Every send or publish ends in `succeeded` (with provider ID), `failed` (with error code), or `outcome_unknown` that is resolved by reconciliation. Never "fire and forget". | Write-ahead `operations` ledger ([ADR-011](architecture/decisions/ADR-011-external-operations-ledger.md)). | Operation state machine tests. Mock "timeout after success" scenario tests. |
| **INV-06** | **Duplicate events and repeated worker executions never create duplicate external side effects.** | Unique `inbound_events.dedup_key`. Unique `messages(social_account_id, external_message_id)`. Unique `operations.idempotency_key`. Reconcile-before-retry. Jobs re-check domain state. Leases. | Tests: same webhook delivered 3×, job executed twice concurrently, worker killed between container creation and publish. All must yield exactly one remote effect in the simulator. |
| **INV-07** | **Scheduled work survives ordinary restarts.** | All scheduled work is rows in PostgreSQL (`jobs`, domain status). Leases recover jobs from crashed workers. Nothing is scheduled in memory. ([ADR-006](architecture/decisions/ADR-006-postgres-job-queue.md)) | Test: enqueue, "restart" (new worker instance), job runs. Test: expired lease is reclaimed and the handler stays idempotent. |
| **INV-08** | **Reports derive from persisted records, never from model-generated numbers.** | Report service is SQL aggregation with documented metric definitions. Narrative is templated text. The LLM is not used for reports. | Test: seeded records → exact expected metrics. Test: report numbers equal counts from the activity log. |
| **INV-09** | **Simulated operations are never presented as real.** | Provider-result `is_simulated` is derived from `social_accounts.provider_kind = 'mock'` and copied to all resulting domain/evidence rows; the UI badges every simulated result. Provider-neutral reusable uploads and their lifecycle audits, and internal development-only `sim_*` state, are excluded. Unbound drafts acquire provider provenance when bound to an account. Workspace demo status and storage choice never establish provenance. Production refuses mock accounts outside explicitly permitted demo workspaces. ([ADR-021](architecture/decisions/ADR-021-simulation-provenance-boundary.md), [ADR-017](architecture/decisions/ADR-017-configuration-and-secrets.md)) | Mock-result propagation and production config tests; E2E badges on inbox, content, reports and notifications; real-provider UI tests. |
| **INV-10** | **Secrets are never committed and never reach the frontend or logs.** | `.env` git-ignored. Secret scan in CI. No secret fields in API schemas (response models whitelist fields). Log redaction processor. Tokens are encrypted at rest and decrypted only inside the provider adapter. | CI secret scan. Test: serialised `SocialAccount` responses contain no token fields. Test: redaction processor masks known keys. |
| **INV-11** | **Publishing and messaging respect actual provider permissions and constraints.** | Capability flags per connected account (from granted scopes and verified features). Messaging window check. 1000-byte text limit. JPEG-only image rules. Publish rate guard. Story without caption. ([platform-capabilities.md](research/platform-capabilities.md)) | Simulator enforces the same constraints. Tests for window-closed, oversize text, missing capability and quota exhausted. |
| **INV-12** | **Important state changes are auditable.** | `audit_logs` row written **in the same transaction** as each state change listed in the audit action catalog ([observability.md §5](architecture/observability.md)). Append-only (no update or delete code path; DB privileges in production). | Tests assert audit entries for each workflow (A–G). |
| **INV-13** | **Integration failures are visible and recoverable.** | Typed provider errors → error codes → operation, account health, notification. `needs_reauth` and `degraded` account states with recovery actions. Dead jobs are visible. | Workflow G tests: token revoked, rate limited, outage, webhook signature failure. |
| **INV-14** | **The core demo remains usable without production credentials.** | Defaults: `LLM_PROVIDER=fake`, `INSTAGRAM_ENABLED_PROVIDERS=mock`, `MEDIA_STORAGE_BACKEND=local`, web channel only. | CI runs the full E2E demo suite with no external credentials and no network egress. |
| **INV-15** | **Every external side effect is preceded by a committed operation record.** No code calls a side-effecting provider method outside the operations executor. | Import rule: only `app/operations/` may call side-effecting provider methods. Code review checklist. | Import-linter test. Grep test in CI for provider calls outside the allowed module. |
| **INV-16** | **Approvals are bound to an exact subject version and payload.** Any change invalidates them; a decision is single-use and expires. | `subject_version`, `payload_hash`, conditional status update, expiry and execution deadline ([ADR-014](architecture/decisions/ADR-014-approval-and-policy-model.md)). | Tests: stale hash → 409; double decision → 409; expired → 409; edit after approval cancels it; executor rejects version mismatch. |
| **INV-17** | **Historical business outcomes are never rewritten.** Sent messages, published content, past fact versions and audit logs cannot be edited to correct history; corrections create new records. | Only the bounded retention, provider-deletion-marker and explicit account-erasure workflows in [ADR-022](architecture/decisions/ADR-022-privacy-redaction-and-audit-retention.md) may remove personal content. They preserve immutable audit/ledger and saved report evidence, and keep unresolved-send evidence until reconciliation completes. `fact_versions` and `audit_logs` remain insert-only. Published content remains read-only. | Sent/published edit rejection tests (`CONFLICT_STATE`); retention boundary/idempotency and saved-report lifecycle tests; account-scoped disconnect erasure and uncertain-send tests. |
| **INV-18** | **The UI never reports success before the outcome is verified.** "Scheduled" ≠ "published"; "approved" ≠ "sent"; `outcome_unknown` is shown as "checking". | Status labels derive from state machines ([state-machines.md](architecture/state-machines.md)), not from request success. | Component tests for status badges. E2E for publishing and failure scenarios. |
| **INV-19** | **Time is unambiguous.** Instants are stored in UTC. Every user-facing interpretation of dates and times ("today", "19:00", "tomorrow") uses the workspace timezone explicitly. | `timestamptz` everywhere. `Clock` abstraction. Workspace timezone passed to parsers and reports. | Tests with a non-UTC workspace timezone and a DST-observing timezone. Report day-boundary tests. |
| **INV-20** | **Demo and development tooling is unavailable in production configuration.** | `DEMO_TOOLS_ENABLED` must be false in production (startup check). Demo routes are not mounted when disabled. | Config tests. Test that `/api/v1/dev/*` returns 404 when disabled. |
